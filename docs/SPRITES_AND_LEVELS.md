# Спрайты и пять уровней в одной сцене

## Быстрый старт

1. Открой `assets/Scenes/ZombieRoad.scene` в **Cocos Creator 3.8.4**.
2. Выдели узел **ZombieRoad → GameSettings**. Дождись импорта новых скриптов редактором.
3. Оставь **Use Sprites** включённым. Картинки зомби задаются в **GameUI/PreLevel → PreLevelWindow → Skins**,
   их вид на дороге — в **Zombie Look** там же. В `Ordinary Car Sprite`,
   `Jeep Sprite`, `Pink Car Sprite`, `Blood Sprite`, `Driver Sprite`
   назначай вложенное поле **Frame**. Это именно **SpriteFrame**, не Texture2D:
   у PNG выбери тип Sprite Frame и перетащи его дочерний spriteFrame из Assets.
4. Настрой Width, Height, Billboard и Bottom Anchor. Спрайты пока не назначены:
   сохраняются прежние префабы/примитивы, игра не требует готовой графики.
5. JSON `assets/resources/levels.json` загружается автоматически. Поле
   **Level Catalog** можно оставить пустым или назначить свой JsonAsset того же формата.
6. Нажми Play, выбери уровень и «Играть». После правки JSON перезапусти предпросмотр,
   чтобы Cocos импортировал и загрузил новую версию ассета.

Сцены для каждого уровня не нужны. JSON задаёт данные, GameFlow создаёт новый World
на старте/повторе/переходе, WorldView отображает ту же раскладку, что использует симуляция.
Существующие сохранения и награды не менялись. Переход на спрайты не включает физику Cocos.

## Звуки

На существующем узле **AudioController** назначен **GameAudioController**:
**Music Clip / Music Volume** — зацикленная музыка, **Button Clip / Button Volume** —
нажатия всех кнопок GameUI (включая карточки), **Hit Clip / Hit Volume** — настоящий
наезд на зомби, один раз на событие гибели. Пустой Clip означает тишину. Громкость 0–1.
Звуковые файлы оставлены пустыми для назначения в инспекторе.

В **GameSettings** рядом с каждым видом машины находятся **Ordinary Car Sound / Volume**,
**Jeep Sound / Volume**, **Pink Car Sound / Volume**. На каждый вид работает только один
канал: он закрепляется за первой вошедшей в кадр машиной. Остальные машины того же вида
молчат до её полного выезда, затем канал получает следующая по порядку появления в кадре.
Уходящая машина плавно затихает на последних 4 мировых единицах до исчезновения её заднего
края; звук следующей нарастает за 0.25 секунды без наложения двух записей. Границы кадра
берутся из текущей ортографической камеры, размеры машин — из габаритов спрайтов.
Стоящая машина сохраняет очередь, но не звучит. Пауза, результат и выход в меню выключают
транспортные звуки и сбрасывают очередь.
Музыка продолжается в меню и на паузе, при скрытии приложения приостанавливается.
Браузер может разрешить воспроизведение только после первого касания/клика.

Компонент использует AudioSource Cocos и не требует изменений или подключения скриптов
из base. Существующий базовый AudioController самостоятельно не знает игровых событий.
После назначения файлов перезапусти Preview. Связи сцены описаны в SCENE_UI.md.

## Настройки изображения

| Поле | Значение |
|---|---|
| Frame | Картинка. Приоритет: назначенный спрайт → старый 3D-префаб → примитив |
| Width | Ширина исходной картинки в мировых единицах |
| Height | Высота; 0 сохраняет исходные пропорции |
| Billboard | Плоскость смотрит в камеру; выключить для вида сверху/пятен/земли |
| Bottom Anchor | Опора внизу картинки; обычно включена у персонажей и боковых машин |
| Flip With Direction | Billboard отражается по движению, плоский вид вращается по курсу |
| Rotation | Поправка ориентации картинки в градусах |
| Lift | Высота над игровой поверхностью; помогает настроить опору изображения |

Для billboard-машин исходная картинка смотрит **вправо**, для плоского вида — **вверх**.
Все машины едут горизонтально по полосам. Для качественного
изометрического вида с разных направлений потребуется соответствующий набор рисунков:
автоматического создания дополнительных ракурсов из одной картинки нет.

UV учитывают прямоугольник SpriteFrame и поворот в атласе; trim сохраняет исходные
пропорции и смещение. У машин Ordinary, Jeep, Pink и всех скинов слизней применяется смешивание по альфа-каналу:
полупрозрачные тени сохраняют прозрачность исходной картинки. Проверка глубины включена,
запись глубины выключена; отбрасываются только пиксели с альфа меньше 1/255.
Остальные спрайты сохраняют unlit alpha-cutout с порогом 0.1.
Материалы/геометрия переиспользуются по SpriteFrame, актёры — через пулы.
Точные контакты используют кэш границ и дерево частей силуэта: отдалённые части отсекаются группами, без упрощения контура, заполнения отверстий или включения теней. Узкая проверка не создаёт массивы проекций. Контуры после построения неизменяемы; при изменении геометрии создаётся новый ContactShape. Проверка `node test-contact-performance.cjs` в tools сравнивает результат с прежним алгоритмом на 4000 случаях и измеряет время сложных синтетических контуров; это не замер FPS отрисованной игры.
Не меняй Frame во время работающего раунда: настройки контента читаются при запуске.

Размер слизней на дороге: **GameUI/PreLevel → PreLevelWindow → Zombie Look → Width**.
Увеличь Width, например в 1.25 раза; при **Height = 0** высота изменится пропорционально.
Если Height задан вручную, увеличь оба значения одинаково. Настройка общая для всех Skins;
размер карточек меню она не меняет. Контакты учитывают новый размер. Перезапусти Preview.

**Use Sprites = false** возвращает отображение через 3D-префабы/примитивы.
JSON-препятствия при этом остаются: это независимое изменение игрового контента.

## Таблица уровней — текущие правила

Компонент **ZombieRoad → LevelSettings** включает новую таблицу и имеет приоритет над старой плотностью, шириной полос и общим лимитом партии из GameSettings. Отключение компонента возвращает прежнюю конфигурацию. Пиксели таблицы — единый масштаб проекта: 3800 px = 36 мировых единиц по X; по Z учитывается наклон камеры 25/24. Размер окна не меняет баланс. VehicleMovementSettings и ZombieMovementSettings используют этот же масштаб.

| Уровень | Полос | Размер дороги, px | Предел партии | Цель | Транспорт снизу вверх | Пауза |
|---|---|---|---|---|---|---|
| 1 | 2 | 3800 × 440 | 4 | 3 | прицеп / доставщик | 4–5 с |
| 2 | 2 | 3800 × 440 | 5 | 4 | прицеп / доставщик | 3–4 с |
| 3 | 3 | 3800 × 660 | 6 | 5 | прицеп / доставщик / прицеп | 3–4 с |
| 4 | 4 | 3800 × 880 | 8 | 6 | прицеп / доставщик / прицеп / доставщик | 5–7 с |
| 5 | 5 | 3800 × 1100 | 10 | 7 | прицеп / доставщик / фургон / прицеп / доставщик | 6–8 с |

Направления снизу вверх: вправо / влево / вправо / влево / вправо. Таблица состава, предела и цели: `domain/LevelRules.ts`. JSON laneDirections по-прежнему записывается сверху вниз; препятствия не перемещены. На пятом уровне финиш ограничен верхним краем дороги с отступом 0.65 мировой единицы, чтобы не спасать слизня внутри крайней полосы.

Первая машина каждой полосы входит независимо через 0–2 с и соответствует составу полосы в таблице. На четвёртом и пятом уровнях старт полос дополнительно разнесён с шагом 1.3 и 1.5 с, чтобы машины не появлялись на всех полосах одновременно. Дальше каждая полоса по очереди чередует доступные на уровне виды транспорта без повторов подряд. Следующая машина ждёт входа хвоста предыдущей, затем Pause Min/Max выбранного уровня. Занятый въезд задерживает появление без наложения машин. Машины создаются за краем камеры. Перестроений и реактивных изменений скорости нет; остановки и бустер сохранены. Зазор очереди Queue Gap Pixels = 55. Старые правила обгона ниже относятся только к выключенному LevelSettings.

Стартовый полёт после отпускания: Flight Speed Pixels = 1760 px/с; Flight Min/Max Pixels = 110–220 px. Максимум уменьшен с 1760 до 220 после замечания о перелёте почти до финиша: прежние 1760 px превышали ширину всей дороги 440–1100 px. Новый максимум равен ширине одной полосы, не зависит от размера экрана и применяется одинаково к стрелке и фактическому полёту. Меняется в ZombieRoad → LevelSettings → Flight Max Pixels. Это изменение дальности относительно исходной таблицы, а не скорости и не обычных прыжков зелёного. Максимальный полёт занимает 0.125 с, после него продолжается индивидуальная ходьба/прыжки. Время 0.25 / 0.375 / 0.5 / 0.625 с из таблицы описывает пересечение 2/3/4/5 полос со скоростью 1760 px/с, но теперь один стартовый бросок всю дорогу не покрывает. При контакте полёт прерывается: препятствие удерживает, борт машины заставляет ждать; неуязвимости нет. Зелёный на старте по-прежнему прыгает.

«Всего» задаёт полный начальный комплект и предел партии: 4 / 5 / 6 / 8 / 10. При подготовке более высокого уровня разово выдаётся разница с ранее выданным комплектом; выбор пятого после первого добавляет 6 малышей. Без потерь партия достигает 10. Счётчик rosterGranted сохраняется: повтор, перезапуск, продажа и перенос в коллекцию не дают новых слизней вместо выбывших. Потери сохраняются и при переходе выше. Старые сохранения без счётчика получают базу не меньше 4 и не меньше текущего суммарного состава партии и коллекции (до 10); история прежних потерь неизвестна, поэтому они не восстанавливаются. Избыток партии перемещается в коллекцию при наличии места, иначе сохраняется вне текущего раунда. Цель не снижается при неполной партии.

Исходный JSON с отключёнными строками сохранён в `.sharrowkin/levels.before-level-table.txt`; активные препятствия сохранены без изменений. Копия сцены до добавления компонента: `.sharrowkin/ZombieRoad.before-level-table.scene`.

## Транспорт по таблице

На узле ZombieRoad компонент VehicleMovementSettings: Trailer — Jeep (330 px/с, 660 × 143 px),
Courier — Pink Car (990 px/с, 220 × 143 px), Van — Ordinary Car (572 px/с, 396 × 143 px).
Фургон доступен с уровня 5, остальные с первого. First Level можно менять в инспекторе.
Speed Pixels задаёт крейсерскую скорость без случайного разброса; замедление бустером,
ожидание транспорта и прежние реакции на слизней/аварии могут временно её изменить.
Length Pixels и Width Pixels задают размер картинки, включая её прозрачные поля.
Масштаб — пиксели расчётного экрана, как у слизней; пересчитывается при подготовке раунда.
Эти размеры заменяют Width/Height машин из GameSettings при включённом компоненте.
Спрайты и звуки остаются в GameSettings. Weight — относительный вес появления:
до уровня 5 прицеп/доставщик равновероятны; с уровня 5 фургон/прицеп/доставщик — 3:1:1.
Плотность по уровням и правила обгона сохранены. Для применения перезапусти предпросмотр.

## Индивидуальное движение слизней после запуска

На **ZombieRoad → ZombieMovementSettings → Profiles** задаются параметры трёх видов.
Skin Index соответствует PreLevelWindow → Skins: 0 — розовый, 1 — зелёный, 2 — жёлтый.
При перестановке Skins обновите индексы профилей. До запуска розовый и жёлтый сохраняют прежнее блуждание.
Зелёный прыгает влево/вправо внутри стартовой зоны с теми же настройками серии; у края отражается.
Его можно захватить мышью или пальцем в воздухе: выбор и стрелка учитывают высоту прыжка.

- WalkAndRest: розовый идёт к финишу со скоростью 120 px/с, 2–4 с движения, 0.5–1 с отдыха.
- JumpSeries: зелёный прыгает по диагонали к финишу, выбирая левую/правую сторону серии.
  Прыжок 132–220 px за 0.25 с, 1–2 прыжка, пауза между ними 0.15 с, отдых между сериями 0.5–1 с.
- Continuous: жёлтый идёт к финишу непрерывно со скоростью 180 px/с.

При включённом LevelSettings дальность обычного прыжка считается в масштабе таблицы дороги: 3800 px = 36 мировых единиц по X. По Z применяется Depth Per Pixel с компенсацией наклона камеры, поэтому диагональ зелёного имеет заданную длину 132–220 px в проекции на поле, а не в мировых координатах. Это длина пути между точками опоры, без визуальной дуги высоты. Один прыжок занимает 3.5–5.8% длины дороги; серия из двух может суммарно пройти до 440 px. Изменение окна не меняет это отношение.
Горизонтальные прыжки в спавне используют тот же масштаб, без изменения дальности. Отдельный полёт после отпускания (Flight Min/Max Pixels) не ограничивается дальностью обычного прыжка. У границ зелёный поворачивает внутрь поля.
Jump Height Pixels задаёт визуальную дугу, но не неуязвимость: машины и препятствия сохраняют действие.
У зелёного таймеры работают уже на старте; запуск продолжает текущий прыжок к финишу.
У остальных профили включаются после запуска. Пауза и задержка препятствием останавливают цикл.
Сила запуска не увеличивает заданную профилем скорость. Legacy сохраняет прежний переход дороги.
Для применения настроек перезапустите предпросмотр.

## Стартовая зона и спасённые зомби

Выбирать и запускать можно только ожидающих зомби (`idle`). После успешного запуска
зомби идёт самостоятельно: повторный захват, прицел и изменение направления недоступны,
в том числе после выхода из препятствия или подъёма с земли. Короткий жест без запуска
и отмена не расходуют возможность запуска. Новый раунд создаёт новую доступную группу.
При захвате мышью или пальцем выбранный слизень останавливается до запуска или отмены.
Замораживаются только его движение и таймеры поведения; остальные слизни и машины продолжают двигаться.
Зелёный при захвате в прыжке сохраняет текущую высоту и фазу; после отмены продолжает прыжок.
Отмена, короткий или запрещённый жест, пауза и скрытие приложения снимают удержание.
Стрелка остаётся привязана к выбранному слизню; направление и сила сохраняются по жесту от точки захвата.
Запуск разрешён только вверх к дороге (отрицательный Z), в том числе по диагонали.
При жесте вниз или строго вбок стрелка скрывается, отпускание не расходует запуск.
Arrow Platform Sprite остаётся под выбранным слизнем на высоте Y = 0.09 независимо от направления жеста. Платформа рисуется камерой игрового мира до отдельного прохода слизней; её UV сохраняют верх и низ исходной картинки.

Высота опоры зомби одинакова на всей дороге (`Y = 0.1` плюс `PreLevelWindow → Zombie Look → Lift`).
Старое визуальное погружение на участке `Z = 5.1…6.6` удалено: оно прятало низ тела
под полосой. Проверка глубины сохранена, чтобы не рисовать зомби сквозь машины.

Стартовая позиция настраивается только в коде: файл
`assets/Scripts/game/domain/Model.ts`, объект `DEFAULT_CONFIG`, поле `spawnOffsetZ`
(сейчас `spawnOffsetZ: 3`).
Например, `spawnOffsetZ: 4` сдвигает всю стартовую группу и границы её прогулки
на 4 мировые единицы ниже по экрану при текущей камере. **0** — исходная позиция;
отрицательные значения сдвигают группу выше. Поле из инспектора удалено,
ограничения −1…2 больше нет. После изменения перезапусти Preview.
При больших сдвигах следи, чтобы старт оставался в кадре и вне дороги:
камера и фон автоматически не подстраиваются.

Это не высота над землёй: **PreLevelWindow → Zombie Look → Lift** меняет именно подъём картинки
по Y для всех зомби, включая идущих по дороге и спасённых. Если ноги «висят»,
проверь Lift, Bottom Anchor и прозрачные поля исходного изображения. Для переноса
стартовой группы используй `DEFAULT_CONFIG.spawnOffsetZ`, а не Lift.

**GameSettings → Finish Offset Z** сдвигает линию засчитывания и места спасённых.
По умолчанию **1**: финиш опущен с Z = −6.2 до **−5.2** (на одну мировую единицу).
Больше значение — ниже по экрану; **0** возвращает прежнее положение.
Старт, дорога, препятствия и картинка фона не перемещаются. Не сдвигай линию
внутрь транспортных полос: спасённые после неё уже неуязвимы. Перезапусти Preview.
Кодовый дефолт: `Model.ts → DEFAULT_CONFIG.finishOffsetZ`.

Перешедшие финиш остаются видимыми в состоянии `saved`, занимают отдельные места
за линией финиша и стоят там до нового раунда. Места выбираются по близости,
центральный проезд оставлен свободным. Они больше не выбираются для запуска,
не получают урон и не засчитываются повторно. На паузе и экране результата
движение останавливается, но сами зомби не удаляются. Повтор/следующий уровень
создаёт новую группу. При увеличении количества или размера спрайтов проверь,
что верхняя площадка помещается в кадре; автоматического изменения камеры нет.

На ровной земле зомби не подскальзываются: случайное падение при пересечении
координат старой канавы отключено. Старое поле `ditchSlipChance` оставлено для
совместимости настроек, но больше не влияет на движение. Пятна крови также не
влияют на движение; дорожные препятствия задерживают, а не роняют.

## Препятствия в инспекторе

**Obstacles Visible** в том же компоненте независимо управляет отображением: включена — прежние картинки/примитивы и отладочные границы, выключена — препятствия не создаются визуально. По умолчанию true. **Obstacles Enabled** по-прежнему отдельно управляет задержкой: для полного отключения препятствий снимите обе галочки, иначе невидимые препятствия могут удерживать слизней. JSON не меняется. После изменения перезапустите Preview.

На узле **ZombieRoad → ObstacleSettings** галочка **Obstacles Enabled** управляет всеми дорожными препятствиями на пяти уровнях. По умолчанию включена: сохраняются точный силуэт, заход на половину тела и задержка 10 секунд. Если снять галочку, слизни проходят сквозь препятствия без задержки; сами картинки и координаты в JSON остаются прежними. Машины действуют независимо. Отключение всего компонента также отключает взаимодействие. После изменения перезапусти предпросмотр; сохранения игрока не меняются.

В **Obstacle Sprites** добавь элементы:

| Type | Картинка | Поведение по умолчанию |
|---|---|---|
| `tire` | Например, шина | Остановка на 10 секунд |
| `pipe` | Труба | Остановка на 10 секунд |
| `tin` | Банка | Остановка на 10 секунд |
| `danger` | Знак (`danger.png`) | Остановка на 10 секунд |

В каждом элементе заполни `Sprite → Frame`. `Type` должен **точно** совпадать с ID
из `obstacleTypes`. У пятен отключи Billboard, Bottom Anchor и Flip With Direction.
Не дублируй один Type в инспекторе: используется первое совпадение.
Можно добавить свои типы с отдельной картинкой; все они задерживают на 10 секунд.
**Добавление картинки в инспектор не размещает препятствие.** Нужны три совпадающих
значения: `Obstacle Sprites → Type`, `obstacleTypes[].id` и `levels[].obstacles[].type`.
Раньше JSON использовал `oil`/`wire`, а сцена — `pipe`/`tin`: поэтому работал только
`tire`. Каталог согласован с названиями сцены; эффекты и координаты других уровней сохранены.

Без назначенного изображения препятствия показываются цветными примитивами.
Старого ряда кустов у места запуска больше нет. Препятствия видны даже при
`Generate Environment = false` (в отличие от декоративного окружения).

**Эти препятствия действуют на зомби, не останавливают и не перенаправляют машины.**
После захода примерно половиной тела на препятствие зомби останавливается на **10 игровых секунд**,
затем сам продолжает путь к финишу. Другие зомби не освобождают его раньше;
повторный запуск во время задержки недоступен. На паузе таймер не идёт.
Наезд передней частью движущейся машины по-прежнему убивает застрявшего;
боковое касание и стоящая машина — нет. Препятствие не даёт защиты от транспорта.
Каждый объект задерживает каждого зомби один раз за раунд, чтобы после освобождения
можно было пройти сквозь него; следующее препятствие снова задержит на 10 секунд.
Перезапуск сбрасывает посещения. Быстрый бросок тоже останавливается на первом
пересечённом препятствии, а не за ним. Длительность задана в
`ObstacleSystem.ts → OBSTACLE_HOLD_SECONDS`.

## Точные контакты спрайтов

При Use Sprites контакты препятствий и передние наезды дополнительно проверяются по
альфа-каналу назначенных SpriteFrame и облику конкретного слизня из PreLevelWindow/Skins.
Пиксели с альфа меньше 0.5 по умолчанию не участвуют: слабые тени не считаются телом.
Порог настраивается в **Contact Alpha Threshold** у Sprite и у **Zombie Look**.
Значение 0.5 означает 128/255; для более плотных теней можно повысить порог.
Это не меняет прозрачность отображения. Автоматическая маска различает только альфа-канал:
если тень непрозрачна, отделить её от тела по одному альфа-каналу нельзя.
Учитываются размер, trim/offset, отражение, поворот, якорь, Lift, масштаб препятствия
и проекция текущей камеры. Проверяется весь отрезок движения, а не только конец кадра.
Для спрайтов радиус JSON больше не определяет задержку; он остаётся запасным вариантом
без картинок. Show Obstacle Bounds показывает только этот запасной круг, не альфа-контур.
Ожидание у одиночной машины проверяется по контурам обоих изображений. Межмашинные
зазоры и плотные очереди сохраняют защитный прямоугольный барьер, чтобы слизень не
шагнул между близко идущими машинами. Борт, зад и неподвижная машина не убивают.
Спрайт препятствия использует исходный контур без сжатия к центру: отверстия и наклонные
края не перемещаются в прозрачные области. Это заменяет прежнее сжатие до 65%.
Только для захвата препятствием из силуэта слизня исключается передняя половина по фактическому направлению движения. Отсечённые части не сжимаются и не смещаются: прозрачные промежутки и тени по-прежнему не участвуют. Половина измеряется по непрозрачной проекции тела с учётом камеры, размера и якоря, а не по прямоугольнику картинки. Заход получается примерно до середины тела, а не обязательно на 50% площади сложного рисунка. Коэффициент задан аргументом `fraction = 0.5` в `SpriteContactGeometry.ts → obstacleBodyShape`; 0 возвращает касание полным силуэтом. Полный контур для машин не меняется. Проверяется весь путь, включая быстрый полёт; остановка происходит у первого достигнутого порога захвата, без телепортации вперёд. Последняя отсечённая форма кешируется для каждого слизня.
Без спрайта запасной круг сохраняет 65% радиуса JSON (`OBSTACLE_CONTACT_SCALE`): в этом режиме нет силуэта, по которому можно измерить половину тела.
При задержке слизень больше не наклоняется на 18°: поза касания сохраняется.
Контур машины обрезается сверху и снизу по 10% высоты проекции, а не сжимается:
для машины вдоль X обрезается Z, для машины вдоль Z — X; оставшиеся части остаются
на своих пикселях, продольные границы сохранены. Коэффициент —
`VehicleContact.ts → VEHICLE_CONTACT_HEIGHT_SCALE`. Он применяется к точному наезду,
запасному контакту без спрайта и ожиданию у машины. Картинки, межмашинные расстояния,
обгон и габариты скрытого спавна остаются прежними.
Контуры кешируются в памяти раунда; кеш повёрнутой геометрии ограничен 256 вариантами.
После замены изображений перезапусти Preview.
Проверка контактов: `npm run test:sprite-contact` из папки `tools`.
В браузере читается изображение Texture2D через Canvas либо несжатый RGBA8-буфер.
Картинка, показанная в интерфейсе (например, слизень в карточке PreLevel), переносится
движком в общий динамический атлас, у которого нет исходного изображения. В этом случае
контур читается из исходной текстуры кадра (`SpriteFrame.original`) с учётом сдвига в атласе.
Если изображение недоступно (например, сжатая GPU-текстура или запрет чтения), выводится
предупреждение в консоль и временно используется прямоугольник SpriteFrame, а не точный
альфа-контур. Неудачная маска и её геометрия не кешируются; повтор чтения — не чаще раза
в секунду. При постоянной ошибке точность не гарантируется: нужен доступный исходный
рисунок без GPU-сжатия. WebP сам по себе не является GPU-сжатием.
MeshCollider не извлекает альфа-контур: текущая mesh-геометрия спрайта — прямоугольник.
Коллайдеры, вручную добавленные к префабам, текущая симуляция не использует.
Для текущих непрозрачных рисунков с полупрозрачными тенями ручные префабы не нужны.

## Кровь и столкновения с машинами

После гибели остаётся **только Blood Sprite** (или запасной blood-префаб/пятно).
Corpse Sprite, Corpse Prefab и поедание трупов удалены. Кровь — только визуальный
эффект: слизни не падают, не останавливаются и не меняют маршрут из-за пятен.
Старое поле Blood Slip Chance сохранено для совместимости, но больше не действует.
Взаимодействие с вышедшим водителем сохранено; его длительность — Driver Eat Seconds.

Убивает только **передний бампер** при движении машины вдоль собственной оси.
Боковой шаг при перестроении, задняя часть, неподвижная машина и упор слизня
в проезжающий борт или низ кузова не убивают. Проверяется каждый фактический участок
пути, включая быстрые машины и оба направления.
Наезд проверяется по всему пути непрозрачного контура машины без отсечения по общей крайней точке X/Z: утопленные и наклонные участки переда тоже сбивают слизней, включая застрявших на препятствиях. Контакт считается передним, только если слизень находится в поперечной полосе кузова и его передняя кромка не отстаёт от переднего контура машины в начале шага. Поэтому слизень, упёршийся в нижний борт или ожидающий сбоку, не погибает, даже когда машина проезжает мимо; после её ухода он продолжает путь без общей неуязвимости от других машин. Размеры контуров, обрезка сверху/снизу и исключение прозрачных полей и теней сохранены.
При упоре в машину слизень останавливается и ждёт освобождения прямого пути,
не обходит кузов, не движется вдоль борта и не возвращается на старт. Ожидание
не имеет таймера: стоящую машину также нужно дождаться. После её ухода движение
к финишу продолжается автоматически, без повторного управления.
Если слизень уже прошёл машину и движется от неё, остаточное пересечение зоны
ожидания не удерживает его: разрешён выход через ближайший край наружу.
Движение внутрь кузова и другие машины впереди по-прежнему блокируют путь.
Плотная очередь одного направления рассматривается как непрерывный корпус:
зазоры между кузовами до 0.6 мировой единицы не являются проходом для слизня.
Ожидание учитывает размеры и смещения машин и проецируемый размер самого слизня,
поэтому он не выступает под переднюю часть следующей машины в этой очереди.
Общей неуязвимости нет: непосредственный фронтальный наезд другой машины опасен.
Касание кузова не включает 10-секундную задержку препятствий.
**Габариты машин берутся из назначенного спрайта**, отдельно для Ordinary, Jeep и Pink:
учитываются Width, Height (0 — исходные пропорции), trim/offset SpriteFrame,
Bottom Anchor, Rotation, Lift, Billboard и отражение/поворот по направлению.
Для billboard прямоугольник изображения проецируется вдоль взгляда камеры на плоскость
контакта зомби (Y = 0.1). Поэтому зона не остаётся у нижнего якоря, когда картинка
занимает место выше него. Используется охватывающий прямоугольник XZ, а не пиксельная
маска альфа-канала: прозрачные участки внутри обрезанного SpriteFrame тоже входят в него.
Эти границы используются при спавне, торможении, перестроении и ожидании плотной очереди.
У одиночной машины ожидание и наезд используют непрозрачные контуры обоих спрайтов.
Между машинами сохраняется зазор 0.2; длинная машина не появится поверх занятого въезда.
Машины создаются целиком за горизонтальной границей текущей камеры с запасом 1 мировой
единицы до ближайшего края картинки. Учитываются размеры и смещение спрайта для каждого
направления. Границы передаются из GameBootstrap до шага симуляции, обновляются при
изменении окна и используются также звуками машин. Машина удаляется только после полного
выезда за противоположный край с запасом; входящая машина за экраном не удаляется.
Без спрайта или при Use Sprites = false остаётся прежний корпус 2.4 × 1.2.
Настройки и направление камеры считываются при запуске игры: после изменения перезапусти
Preview. Автоматическая камера меняет позицию/масштаб, но не направление; для вращаемой
во время игры камеры потребуется пересчёт границ.

**GameSettings → Vehicle Offset Z** сдвигает только транспорт вместе с его зонами
столкновения относительно полос. Начальное значение **0.4** опускает машины немного
ниже; больше — ниже, **0** возвращает прежнюю траекторию. Это не Lift: движение и наезды
смещаются вместе с картинкой. Полосы, фон, зомби, препятствия и финиш не перемещаются.
Значение 0.4 — начальная подгонка, окончательно подбери в Preview.

## Выход водителей

**GameSettings → Driver Exit Enabled** — разрешает выход водителей из машин.
По умолчанию включено: сохраняется прежнее поведение (шанс **Driver Exit Chance**
после наезда обычной машины на зомби и выход после аварии, если машина ещё никого
не сбила). Выключено: водитель не выходит ни после наезда, ни после аварии;
машина не останавливается для осмотра водителем. Остальная логика столкновений
не меняется. Настройка общая для пяти уровней. После изменения перезапусти Preview.

## Плотность транспорта

Частота появления машин постепенно растёт от первого уровня к пятому.
В `World.ts` множители интервала для уровней 1–5: `[2, 1.7, 1.4, 1.2, 1]`.
Они увеличивают прежнюю паузу между попытками появления: на первом уровне машины
появляются примерно вдвое реже прежнего, на пятом частота не изменена.
Базовая настройка **GameSettings → Traffic Interval** сохранена; итоговая пауза равна
`trafficInterval / (1 + (level - 1) * 0.12) × множитель × случайное число 0.8…1.3`.
Первая попытка появления остаётся через 1.2 игровых секунды. Занятый въезд может
отложить появление; скорости, ограничения количества машин, обгон и полосы не изменены.
Для применения перезапусти предпросмотр; для сайта пересобери игру.

## Полосы движения

В `assets/resources/levels.json` поле `laneDirections` задаёт полосы **сверху вниз
по экрану** (от отрицательного Z к положительному). `left` — влево, `right` — вправо.

| Уровень | laneDirections | Центры полос Z |
|---|---|---|
| 1–2 | `["left", "right"]` | −0.9, 0.9 |
| 3 | `["right", "left", "right"]` | −1.8, 0, 1.8 |
| 4–5 | `["right", "left", "right", "left"]` | −2.7, −0.9, 0.9, 2.7 |

**GameSettings → Lane Widths** — массив ширин **одной** полосы в мировых единицах
для пяти уровней: элемент **0 → уровень 1**, **1 → уровень 2**, **2 → уровень 3**,
**3 → уровень 4**, **4 → уровень 5**. В текущей сцене сохранено `[5, 5, 5, 5, 5]`.
Общая ширина группы = число полос × значение для выбранного уровня.
Например, `[5, 4, 3, 2, 2.5]` даёт общую ширину 10 / 8 / 9 / 8 / 10.
Выбранная ширина применяется к транспорту, цветным полосам и разметке при запуске,
повторе и переходе уровня. Пропущенные или нечисловые элементы используют дефолт
соответствующего уровня (1.8); значения меньше 1.4 ограничиваются до 1.4.
Таблица центров выше приведена для ширины 1.8.
**GameSettings → Lane Offset Z** — смещение центра группы, общее для всех уровней.
По умолчанию **0**; положительное значение (например, **2**) опускает полосы
и транспорт ниже при текущей камере, отрицательное поднимает. Ограничения диапазона нет.
`centerZ = laneOffsetZ + (index - (count - 1) / 2) * laneWidth`.
Верхняя полоса имеет индекс 0; таблица выше приведена для нулевого смещения.
Сдвигаются цветные полосы, межполосная разметка и траектории машин, но не фон,
дорожное основание, разделитель, препятствия, старт или финиш. Подбирай смещение
в пределах дороги и кадра. После изменения перезапусти Preview.
Минимум 1.4 сохранён для старых 3D-габаритов; для крупных спрайтов подбирай ширину
полос по их новым границам и зазору 0.2. Если габариты захватывают соседнюю встречную
полосу, новый встречный транспорт ждёт свободного проезда за экраном: он не появляется,
пока конфликтующий поток не покинет дорогу. Это предотвращает встречную блокировку
без уменьшения коллайдеров или изменения ширины полос. При слишком высоких картинках
потоки поэтому могут идти по очереди; для одновременного движения увеличь ширину полос
или уменьши высоту картинок. Верхнего лимита ширины нет.
Кодовые дефолты: `Model.ts → DEFAULT_CONFIG.laneWidths`; массив инспектора имеет приоритет.
Дорожное основание остаётся не уже 7.2, чтобы не перемещать вручную заданные препятствия;
при большой ширине полос основание и граница `onRoad` расширяются симметрично.
Финиш, канава, камера и картинка фона не растягиваются: слишком широкая дорога может
перекрыть их — подбирай размер с учётом сцены.

Поверхность полос чередуется сверху вниз: **#956147**, **#8d5c44**, снова #956147…
Цвета заданы в `WorldView.ts → buildLaneSurfaces`, используются unlit-материалы.
Это заливка всей полосы, не цвет пунктирной разметки. Она рисуется и поверх назначенного
плоского ландшафта (при стандартном Lift = 0), ниже препятствий и персонажей.
Перекрёстка (поперечной дороги) и разделителя с перекладинами нет ни на одном уровне:
уровни различаются только количеством и направлением полос. Препятствия, финиш и стартовая зона не перемещаются.
Спавн машин и генерируемая разметка используют одну конфигурацию.
Ordinary Car и Pink Car могут обгонять более медленную или остановившуюся машину;
Jeep не обгоняет. Обгон начинается при догонянии ближайшей помехи по габаритам:
зазор 0.2 плюс расстояние сближения за 0.5 секунды, а не за несколько корпусов.
Учитывается скорость всей очереди впереди, а не только заданная скорость первой машины.
Поперечная скорость перестроения и возврата равна собственной скорости машины;
последний шаг ограничен оставшимся расстоянием до полосы. При упоре в задний бампер
боковой шаг проверяется отдельно от движения вперёд, поэтому торможение не блокирует
выезд на свободную полосу. Бустер замедляет обе составляющие движения одинаково.
Временное ускорение розовой машины сохраняется и при обгоне. Далёкая попутная
машина на соседней полосе, которая удаляется быстрее обгоняющей, не запрещает манёвр.
Наезд при перестроении проверяется отдельно на боковом шаге и на участке движения
вперёд, а не по воображаемой диагонали между началом и концом кадра. Боковой шаг
не убивает: опасен только передний бампер при движении вдоль оси машины. Проверяются
непрозрачные контуры на всём фактически пройденном участке. Слизень, упирающийся
в проезжающий борт или низ машины, ждёт и не погибает; после освобождения пути
он продолжает движение. Для обгона нужна свободная соседняя полоса и достаточная ширина
для реальных габаритов обоих спрайтов. Допускается временное занятие встречной полосы,
но только когда весь коридор манёвра свободен от другого транспорта. На время обгона
новые машины в этот коридор не выпускаются. Сначала машина плавно перестраивается,
проезжает вперёд и с запасом возвращается в исходную полосу. При отсутствии места
обгон не начинается; размеры машин и направления обычного потока не меняются.
Точка обгона учитывает смещение корпуса относительно нижнего якоря картинки. При
необходимости она сдвигается от центра соседней полосы максимум на четверть её ширины,
чтобы между спрайтами оставался зазор 0.4. Габариты не уменьшаются. Геометрическая
проверка не требует, чтобы нижний якорь совпадал с центром корпуса на краю дороги.
Машина позади больше не запрещает обгон автоматически: проверяется запас расстояния
на время перестроения и её скорость. Встречный транспорт впереди и чужие незавершённые
обгоны по-прежнему блокируют манёвр. Проверки включают реальные спрайты и ширины
полос из сцены на всех пяти уровнях, в обоих направлениях и с машиной в хвосте очереди.
Розовая машина после аварии ускоряется, но больше не разворачивается против потока:
разворот на занятой полосе мог навсегда заблокировать дорогу.

Старый JSON без `laneDirections` получает настройки по номеру уровня из
`LevelCatalog.ts → defaultLaneDirections`. Явное поле допускает 2–4 значения
`left`/`right`; ошибочные значения показывают ошибку загрузки.
Цветные полосы перекрывают рисунок фона внутри группы; сам файл изображения не меняется.
Нарисованные края дороги вне группы нужно согласовать с координатами симуляции.
При выключенном **Generate Environment** цветные полосы тоже не создаются.
Перезапусти Preview после правок.

## Как редактировать JSON

В файле пять раскладок: 3, 4, 19, 6 и 8 препятствий.

### Третий уровень — по референсу

19 препятствий: 7 шин, 2 трубы, 5 банок и 5 знаков. Раскладка разбита пустыми
строками на четыре ряда сверху вниз: `z = -2.7, -0.9, 0.9, 2.7`.
Горизонтальные позиции перенесены приблизительно с изображения шириной 2000 px:
`x = (pixelX / 2000 - 0.5) * 30`. Это пропорциональный перенос в существующую
дорогу, не пиксельное совпадение кадра: камера и фон не менялись. Шина около центра
во втором ряду частично закрыта поездом на референсе; её положение оценочное.
Масштабы 0.52 для шин/знаков и 0.28 для труб/банок сохраняют соотношение размеров
на образце при Width = 1.4. Радиусы уменьшаются вместе с масштабом.
Машины и зомби не зафиксированы в позах со скриншота и продолжают двигаться по игровой логике.
В сцену добавлен `danger` с импортированным SpriteFrame `danger.png`; соответствие
самой картинки знаку требует визуальной проверки в редакторе.

Один объект — одна компактная строка, удобно редактировать как таблицу:

```json
{ "id": "tire-1", "type": "tire", "x": -6, "z": 2.1, "rotation": 15, "scale": 1 }
```

| Поле | Назначение |
|---|---|
| id | Уникальное имя объекта внутри уровня |
| type | Ссылка на `obstacleTypes[].id` |
| x | Положение слева/справа: центр 0, любое конечное число без ограничения диапазона |
| z | Положение поперёк дороги: любое конечное число без ограничения диапазона |
| rotation | Поворот картинки/примитива, по умолчанию 0 |
| scale | Масштаб изображения и стандартного радиуса, по умолчанию 1 |
| radius | Необязательно: радиус запасного контакта без спрайтов вместо radius типа × scale |

Зомби появляются при положительном Z (примерно 9…12), идут в сторону **−Z**,
финиш находится на Z = −6.2 + Finish Offset Z (по умолчанию **−5.2**).
Центры полос зависят от уровня (см. таблицу выше).
Координаты `x` и `z` задаются вручную и сохраняются без обрезания и проверки
границ дороги, в том числе с учётом радиуса. Радиус — круг, rotation его не меняет.
Выход препятствия за дорогу или кадр не запрещает загрузку; камера и фон
автоматически не расширяются, поэтому видимость и доступность проверяй в Preview.
Включи **Show Obstacle Bounds**, чтобы увидеть запасные круги срабатывания для режима без спрайтов.
При назначенных картинках срабатывание определяется видимыми контурами, а не этими кругами.

В `obstacleTypes` радиус `radius` (0.1…2) определяет область столкновения.
Старые `effect` (`trip`/`slip`/`snare`) и `chance` (0…1) сохранены для совместимости
JSON, но больше не меняют задержку: она обязательна для всех типов.
`effect` различает только запасные примитивы без спрайта. Иммунитет после падения
и модификаторы скольжения/застревания не отменяют задержку препятствием.
У уровня: `id` (1…5), `laneDirections`, `obstacles`. Пустой массив препятствий разрешён.
Разделителя и перекрёстка нет: уровни различаются только полосами и препятствиями.
Старые поля `median`/`intersection` в JSON игнорируются.
Пересекающиеся зоны разрешены: первым срабатывает ближайшее по пути препятствие;
при одинаковой точке входа используется порядок JSON.

Файл `docs/levels.schema.json` даёт подсказки JSON-редактору.
Дополнительная runtime-валидация проверяет уникальность ID, ссылки на типы, конечные
числа и допустимые параметры типов/размеров, но не границы координат. При ошибке — экран с путём ошибочного поля и
повтором загрузки, а не тихая подмена на другую раскладку. После изменения файла на
диске надёжнее перезапустить preview: импортированный JsonAsset кешируется движком.

## Ландшафт

В **Landscape Sprites** добавь элемент, назначь `Sprite → Frame`:
- `Level = 0` — общий фон; `1…5` — отдельный фон соответствующего уровня;
- по умолчанию плоскость XZ, центр `(0, 2)`, размер `36 × 25`;
- фон выбранного уровня имеет приоритет над общим;
- назначенный фон заменяет генерируемые землю, асфальт, разметку, канаву и финиш;
  цветные полосы остаются отдельными видимыми объектами;
- при выключенном Generate Environment фон тоже не создаётся — используется твоё окружение.

Картинка **не меняет** полосы, финиш и канаву: нарисованные ориентиры нужно совместить
с координатами симуляции. Если фон содержит уже готовую перспективу, можно включить
Billboard и подобрать Width/Height/X/Z, но плоский вид сверху проще точно совместить.
Пять разных фонов тоже назначаются в одной сцене.

## Проверки

В каталоге `tools` (Node.js 22):

```text
npm ci
npm test
npm run test:vehicle-sprites
npm run test:vehicle-routing
npm run typecheck
```

Тесты исполняют настоящие доменные модули без Cocos-моков: валидация, движение,
все эффекты, иммунитет, освобождение, столкновение с машиной, пять переходов,
повтор, пауза и детерминированный шаг. Typecheck использует декларации установленного
Cocos через `temp/declarations` — предварительно открой проект в редакторе.

Ручная приёмка после назначения графики: запустить каждый уровень, проверить
совпадение радиусов с изображениями, запустить зомби в каждую опасность, повторить
раунд, проверить машины и фон каждого уровня. Автотесты не
подтверждают визуальную ориентацию пользовательских изображений.
